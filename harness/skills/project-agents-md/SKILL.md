# 维护项目说明

## 1. 写概要与入口

按以下顺序组织，无内容的小节省略：

| 小节 | 内容 |
| --- | --- |
| 项目是什么 | 用途、服务谁、解决什么长期问题 |
| 业务概要 | 主要业务、核心对象及关系 |
| 设计概要 | 技术组成、模块分工、依赖方向与必要原因 |
| 怎么运行 | 环境、安装、启动、构建、测试与配置入口 |
| 目录地图 | 主要目录用途，帮助找到修改位置 |
| 去哪里找 | 业务、接口、数据模型、配置和测试的资料入口 |
| 数据流动概要 | 数据来源、主要处理、保存或发送位置 |
| 本项目的约定 | 长期特殊要求、适用范围与原因 |

标题用项目名，小节用 `##`。设计解释整体安排，目录说明位置，资料入口按阅读目的组织；详细内容给链接，不列全部文件和函数。资料入口只链接长期维护的文档与代码，临时记录不加入。

## 2. 原处维护

读完整说明、README、业务设计、相关代码与脚本，再更新受影响部分。结构变化或目录地图无法帮助定位时按实际调整；已有明确决定优先。

不写阶段、进度、某次故障、具体坑、临时办法、检查结果和历史。问题改变长期设计或运行要求时，更新概要，不留经过。

共同协作规则不复制。尽量不超过 150 行，长度只作提示，必要内容不因数字删除。

## 3. 检查

首次创建可用 `scripts/dir_overview.py`查看目录，按用途整理输出。命令来自实际脚本与配置，检查结果在回复中说明。

运行 `python <本 Skill 所在目录>/scripts/check_agents_md.py <项目根目录>`，再人工检查业务、设计与入口是否准确。

Claude Code 用 CLAUDE.md 的 `@AGENTS.md` 导入并保留原内容；其他工具沿用实际读取位置。
