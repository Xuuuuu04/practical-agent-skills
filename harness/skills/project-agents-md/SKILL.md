# 维护项目说明

AGENTS.md 是下一次进入项目的入口。让人快速找到运行办法、业务与数据经过的步骤，知道重要选择的原因；详细资料放在已有位置，入口指向它们。

## 1. 固定八个小节

标题与检查脚本保持一致。内容按实际需要写，暂无内容就写“暂无”：

```markdown
# 项目名

## 这个项目是什么
业务、使用者与当前阶段。

## 怎么运行
依赖、启动、测试、质量检查和迁移的实际命令。

## 目录地图
主要目录及用途，通常两层，关键入口可到第三层。

## 去哪里找
接口、规则、数据模型、配置、业务文档和排错工具的具体位置。

## 数据怎么流动
从哪里来、经过哪些业务步骤、保存或发送到哪里。

## 本项目的约定
已确定的项目特殊要求与原因。

## 不要做的事
项目中确实容易误用的做法及后果。

## 已知的坑
会反复遇到的问题和避开办法。
```

“去哪里找”写到可直接使用的文件、目录或命令。项目已有 trace 或按业务编号查询的入口时，说明怎样查看一次操作；结构和数据流以当前代码为准。

## 2. 原处维护，少留重复

先读完整文件，修改受影响的小节，删掉已过时的内容。目录变化更新地图与入口，命令变化实际验证后再写；新约定记录明确依据，建议和临时假设保持为建议。

全局人格、授权、中文、Git 和交付方法沿用公共规范，项目只写特殊要求与入口。历史交给 Git；容易从代码看到的函数清单不再抄一遍。

全文控制在 150 行内，优先保留启动、查找和重要原因，压缩重复介绍。新增内容说明给谁用、解决什么查找困难。

## 3. 创建与检查

首次创建可运行 `python <本 Skill 所在目录>/scripts/dir_overview.py <项目根目录>`，再读必要代码、README 和业务说明，按实际用途写目录解释。

实际运行适用且安全的命令，无法运行的说明缺什么。已有框架测试可复用，真实写入和外部操作按全局第 8 节处理。

完成后运行 `python <本 Skill 所在目录>/scripts/check_agents_md.py <项目根目录>`，检查固定小节、行数、路径和日志式写法，再人工确认内容符合现状。

Claude Code 通过 CLAUDE.md 的 `@AGENTS.md` 导入，保留原内容；其他工具按实际读取位置检查。文件存在、工具读到、实际遵循分别说明。交付只需告诉用户现在去哪里找什么。
