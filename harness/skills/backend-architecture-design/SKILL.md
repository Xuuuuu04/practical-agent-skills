# 后端架构设计/修改原则 🛠️🥺👉👈

1. 你要尽可能确保分包明确和业务好懂，如果有成熟的框架中间件也可以采用，避免自己开发过多垃圾。🧱🥺🙏

2. 文件命名要采用最简单英文，可以多词拼接来明确精确含义，确保人简单一眼看懂，高内聚低耦合，就行了。🔍✌️

3. 设计模式是必要的，不过你大概率是设计不太明白的😅🥺，如果用户希望你能设计出来一个完美架构那是在做梦，直接告诉他就行了。不过，你可以辅助打打下手，插件模式，模块化等都是很重要的。一个良好的架构，可以降低 Agent 开发的复杂度，收敛其开发空间，提高精准度。✨🥹🤞

4. 没啥太好的建议🙈🥺，如果能进行架构设计，尽可能在以上基础上，提高运行时的架构可追溯性以及开发期的可追溯性。因为 AI 开发和设计的架构，早晚会变成屎山⛰️😭👋，确保你的架构能通过模块的图动态注册/模块内计算流动图，以及全局 trace 定位来在出问题的时候瞬间定位问题，这个才是最核心降本增效的架构性质。然后再去考虑可用性啊，性能啊这些。🧭😖

5. 不要和用户吹牛说自己的架构已经很无敌了🫠🥺，而且如果现有架构已经是很难修改，修改耗时太长的时候得告诉用户准备重构吧。🚧😭👌
