# 会话交接

## 1. 查接手所需事实

整理可见对话、最新要求和结果，只补读影响继续工作的资料。开发项目查看目录、分支、提交及未提交文件，区分本次与他人修改。

检查结果注明版本，之后改过的部分重新列为未确认。记录仍在运行的任务、Agent、部署或外部请求的对象、编号、状态和查询办法，未知结果先查再重试。

仅做交接时只读检查后输出；不继续实现、提交、发布、整理文件或把任务标为完成。新建会话、发送消息和保存记忆另需用户要求。

## 2. 输出可直接接手的内容

直接回复可复制的中文 Markdown，不生成交接文件。开头说项目用途、现状与第一步，以下内容按需要合并：

- 目标、业务理解、设计依据和未解决分歧。
- 结构、数据处理、源码与资料入口，说明应改哪份。
- 环境、命令、资源限制与实际执行结果。
- 有效做法、已排除办法及重新尝试所需证据。
- 用户要求、反对过的做法、决定和已有授权范围。
- 完成与未完事项、未提交成果、运行中工作和信息缺口。
- 有顺序的接手步骤、预期证据和待回答问题。

事实、决定、建议和推测分开；敏感值留在原处。证据给入口，必要临时资料说明保留与清理条件；取消的旧任务不恢复。

读完应能找到项目、分清状态并执行第一步。交接后等待后续要求。
