# 代码重构与整理

## 1. 确定范围

指定包与顺序就逐个完成。整个项目的整理先给包的大小、实际问题和推荐顺序，请用户确定范围。

查入口、接口、表、配置和定时任务，确定需要保留的行为。移动改名更新必要的包外引用；无关问题只提建议。

记录原提交，保护未提交与未跟踪文件。运行已有测试，为未覆盖入口准备输入和旧输出；动态字段确定比较办法。

## 2. 整理结构

一条规则维护一处，文件说明独立用途。无法说明拆分理由的重叠文件可以合并，正常的独立业务不为减少文件数硬合。

删除前查调用、配置、动态加载、命令和文档引用，并找废弃依据；搜索不到引用不足以证明无用。后端结构按 backend-architecture-design，目录变化更新 README 与项目入口。

## 3. 检查长度与行为

开始和结束运行 `python <本 Skill 所在目录>/../pre-delivery-check/scripts/change_health.py --repo <项目根目录> --package <包目录> --agents <当前全局规范文件>`。

项目明确限制优先；以下为脚本默认提示值，超出后检查重复与独立步骤，不硬拆连续计算：

| 对象 | 提示值 |
| --- | --- |
| 代码文件 | 400 行 |
| Python 函数 | 60 行；其他语言人工看 |
| 文档 | 300 行 |
| Shell 脚本 | 200 行 |
| SQL 单条语句 | 80 行 |
| 日志 | 每条一行，保留定位字段 |

每组完整改动比较受影响入口，最后比较整个包。同一输入与初始数据满足确认的兼容规则；整理引入的差异修正，旧错误按授权处理。

行为一致不自动证明业务正确。差异原因用 debug 查清，交付用 pre-delivery-check。
