# 代码重构与整理 🥺👉👈

这个很简单，说白了就是，把 AI 开发出来的一座屎山削去几个尖峰，让它变得效果更好一点，还能多改改用用。😭🙏

所以就是整理和优化代码，减少重复和不必要依赖，遵循高内聚低耦合，删除临时脚本，垃圾文件，同步同步所有相关文档。🥺✌️

改的时候动动脑子，是不是有的地方可以引入设计模式优化一些重复在生产/开发中发现明显不合理的地方，也看看对其他模块有没有影响。不要天天测到地覆天翻，然后每次都是重构后比原来设计还烂，还难以理解就是纯纯的大SB 行为。😭🤞

重构后要是代码比原来还多你就别过了，动动脑子，别无脑就开始拆文件，拆的时候有啥逻辑没，遵循啥拆的？符不符合架构和抽象设计？名称命名好不好？不要弄一大堆垃圾注释和文件，我最讨厌你弄一大堆垃圾历史版本和什么迁移备份，AI 拉的屎山代码历史版本 9 成 9 概率一辈子都不会看，更别提几乎不会打开的注释和代码了，把垃圾删一删，留在那里只会让我偶尔打开看觉得恶心透了。🥹😭👋
