# 界面设计

## 1. 按用户任务组织

先看业务、现有页面、品牌与公共组件。用一个人的完整操作确定内容，例如客服找订单、确认退款金额、提交、回到列表。

菜单按业务任务组织，主要动作写对象与结果，低频设置容易找到。必要费用、条件和后果在操作前说明；保存不能暗中发送通知。

## 2. 选择页面形式

| 任务 | 形式 |
| --- | --- |
| 简单字段或补充说明 | 页内编辑或展开 |
| 短选项与局部动作 | 菜单或小浮层 |
| 从列表快速查看后继续浏览 | 抽屉或侧面板 |
| 暂停当前操作的短决定 | 弹窗 |
| 长内容、复杂编辑、多步骤或分享链接 | 独立页面 |

同类操作形式一致。边看列表边编辑时允许操作背景；需要阻止背景时处理键盘进入、退出和返回。层层叠面板时重新考虑独立页面。

返回列表保留筛选、排序、分页和位置。独立详情支持刷新、直接访问、复制链接和浏览器返回，必要时保留草稿。

## 3. 设计动作与状态

状态与操作依据已确认的业务和实际结果，文案不承诺未实现的行为。

| 状态 | 表现 |
| --- | --- |
| 读取中 | 显示加载，布局稳定 |
| 无记录或无筛选结果 | 区分原因，给创建或清除条件入口 |
| 提交中 | 避免重复点击，服务端处理重复请求 |
| 完成 | 更新真实状态，重要结果可再次找到 |
| 确认失败 | 就近说明问题，保留输入，允许修改或重试 |
| 超时、结果未知 | 超时或无记录仍属未知；重试需原请求已结束并明确失败，或服务端按同一请求标识判重 |
| 无权限或状态不允许 | 按业务隐藏或说明，后台继续检查 |

返回、关闭、取消编辑、撤回申请和更正记录各按实际业务处理。离开未保存内容时提供适用的保存或放弃办法；操作记录放在业务对象附近，简单偏好无需记录中心。

## 4. 统一视觉

视觉方向符合内容用途，用真实长度的中文、数字和多种状态检查布局。颜色、字体、间距与动效通过公共样式维护；组件库先用主题配置，自写组件只抽取实际复用部分。

靠排版和分组组织内容。默认避开左侧亮条大卡片、重复标题副标题、无用统计卡和装饰横幅；已有品牌要求优先。

正文与数据对比清楚，中文与备用字体可用，金额和单位便于比较。文档预览与导出用确认模板，不扩展到操作界面。

## 5. 操作检查

走完主要任务，检查返回、取消和失败恢复。键盘位置可见，控件有名称，状态不只依靠颜色；窄屏和放大后仍可读，宽表局部滚动。

浮层能进入、退出并返回合理位置。动效表达状态变化，尊重减少动态效果设置；目标设备无法检查时说明。

细节查[场景与资料](references/patterns.md)，交付用 pre-delivery-check，实际错误用 debug。
