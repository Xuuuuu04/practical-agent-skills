# 界面设计

好的界面让人知道自己在哪、下一步做什么、操作后发生什么。审美贯穿内容、顺序和细节：每个元素各得其所，必要信息容易看到，常用操作顺手，整套页面有一致的性格。

先看业务、现有页面、品牌与公共组件。发现安排妨碍使用，用具体操作解释影响，提出相应改法；已有明确风格就沿用。

## 1. 沿着一个人的任务设计

说清谁在什么场景完成什么事，例如客服找到订单、确认退款金额、提交、回到原列表。字段、按钮和区块帮助判断、操作或理解结果，菜单按业务任务组织；后台接口数量不决定页面数量。

先展示当前需要的内容，低频设置放在容易找到的位置。主要动作明确，按钮写具体对象与动作，名称覆盖实际结果；“保存联系人”不能暗中发送通知。必要费用、条件、错误和后果保持可见，未定业务用 business-rules。

## 2. 给信息合适的位置

导航表达真实的业务与上下级关系，标签页切换同一对象的相关内容。按任务选打开方式，同类操作保持一致：

| 任务 | 合适的形式 |
| --- | --- |
| 简单字段或补充说明 | 页内编辑或展开，保存和取消清楚 |
| 短选项与局部操作 | 菜单或小浮层 |
| 从列表快速查看、处理后继续浏览 | 抽屉或侧面板，保留列表位置 |
| 需要暂停当前操作的短决定 | 弹窗，说明对象、后果和退出方式 |
| 长内容、复杂编辑、多步骤或需要分享链接 | 独立页面，必要时保留草稿 |

需要边看列表边编辑时，让背景仍可操作；需要阻止背景操作时，处理键盘进入、退出和返回。连续叠加面板难以表达层级时，改用独立页面。

返回、关闭和取消各有含义。返回列表保留筛选、排序、分页和位置；独立详情支持刷新、直接访问、复制链接和浏览器返回。

## 3. 设计动作之前与之后

操作能否执行、处理中怎样显示、成功去哪里、失败怎样继续、是否可撤回，都来自业务状态与实际结果。

| 状态 | 应有的表现 |
| --- | --- |
| 正在读取 | 明确加载，主要布局稳定，避免闪出无数据 |
| 无记录或筛选无结果 | 区分原因，给适用的创建或清除条件入口 |
| 正在提交 | 表达处理中，避免重复点击，服务端也处理重复请求 |
| 已完成 | 更新真实状态，重要结果有可再次找到的记录 |
| 确认失败 | 指出问题位置，保留输入，给适用的修改或重试办法 |
| 超时、结果未知 | 先查询结果，再决定是否重试 |
| 无权限或状态不允许 | 按业务隐藏或说明原因，后台继续检查权限 |

取消编辑、撤回申请和更正记录按业务分别设计，说明条件与后果。需要凭据的操作在业务对象附近显示谁何时做了什么；简单偏好无需记录中心。

表单保留字段名称、必要格式和就近错误说明。离开未保存内容时，按实际保存方式处理继续、保存或放弃，确认步骤对应真正重要的后果。

## 4. 把品味落在具体选择上

先确定符合内容的视觉方向。操作密集页面重视扫描与比较，展示页面可以更有表现力；用真实长度的中文、数字和多种状态检验布局。

颜色、字体、间距、圆角、阴影和动效由公共样式表达，同一用途一致。组件库先用主题配置，补充样式集中且限定范围；自写组件提取真正复用的部分，业务布局保持清楚。普通、悬停、键盘选中、处理中、禁用和错误状态一并考虑。

靠排版、间距与分组组织内容，卡片用于需要独立浏览或操作的一组信息。默认避开左侧亮条大卡片、重复标题副标题、无用统计卡和占据首屏的装饰横幅；已有品牌要求优先。淡色或纹理服务于主题，正文与数据保持清晰对比。

字体按标题、正文、字段、辅助说明和数字选用，保证中文与备用字体可用，金额和单位便于比较。公文或报告的预览与导出采用已确认模板，操作界面保留自己的字体规则。文案沿用全局第 9 节，帮助放在需要解释的位置。

## 5. 亲自走完使用过程

先做能操作的主要任务，再扩展相关页面。用键盘、目标设备、窄屏和文字放大检查；选中位置可见，控件有名称，状态不只依靠颜色。浮层打开、关闭与返回自然，宽表局部滚动，正文和表单仍可读。

动效解释状态与位置变化，简短一致，尊重减少动态效果的设置。细节标准和争议场景按需读 [场景与资料](references/patterns.md)。

按 pre-delivery-check 从入口操作到结果，检查返回、取消和失败恢复。实际错误交给 debug 查原因，共用组件问题修在共用处。先处理无法完成、误操作和误解，再完善阅读与一致性。交付给可操作入口，模拟数据、未连接后台及未检查部分如实说明；截图好看与业务可用分别判断。
