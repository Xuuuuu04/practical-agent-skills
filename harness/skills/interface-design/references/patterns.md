# 场景与资料

这些例子说明怎样作设计判断，不代替真实项目的业务规则。先用项目已有约定，仍不明确且会改变结果时，按全局规范第 8 节处理。

与用户讨论时先沿着一个人的操作讲清楚，再按需要查下面的表；这些表供设计与检查使用，不要求整张贴进每次回复。聊天语气沿用全局第 9 节，界面文案仍按业务和品牌要求写。

## 1. 从任务组织界面

假设客服日常要找到待处理工单、看清问题、回复客户。后台同时有查询、标签、同步、刷新缓存、重试任务等接口。

| 安排 | 原因 |
| --- | --- |
| 工单列表优先显示需要判断和处理的信息，常用筛选容易找到 | 客服先找到要处理的对象，无需理解接口划分 |
| 标签、回复和状态变化围绕当前工单组织 | 同一个用户任务可以用到多个接口，不需要多个顶级菜单 |
| 同步和缓存操作只在实际需要这些能力的维护入口出现 | 用户看不懂也不需要操作的内部能力，不放进日常业务页面 |
| 状态颜色带有文字，数量说明对应的范围 | 避免用户把全部工单数误认为当前筛选后的数量 |

大卡片高亮竖条、固定标题加副标题，是本套规范默认避免的视觉形式。不能仅凭这些形状认定页面由 AI 制作，也不要为去掉卡片而拆散原本属于一件事的内容。

## 2. 同样是详情，打开方式可以不同

客服连续扫看几十条工单，短预览适合侧面板；要长篇回复、比较多个附件或把链接交给同事，就更适合独立详情页。界面可以同时提供快速预览和明确的详情入口，但两者的内容名称与状态应一致。

若用户需要边看列表边修改，先判断面板是否允许操作背景。遮住背景的抽屉与弹窗一样会中断操作，并不会因为出现在右边就更适合所有任务。不要把多层抽屉能实现，当成应该使用它的理由。

保存后返回，列表保留原有筛选和位置，并显示修改后的状态；用户直接打开详情链接时，仍有明确的所属业务入口。返回路径不依赖用户此前一定从列表进入。

## 3. 撤回、取消与记录

以下预约规则仅用于例子：未确认的预约申请允许撤回；已经到店的记录只允许按业务规则申请更正。

| 当前情况 | 合适的说明和操作 | 容易造成的问题 |
| --- | --- | --- |
| 尚未提交 | 取消编辑；有未保存内容时说明如何保留或放弃 | 关闭窗口时把用户输入直接清空 |
| 已提交，等待确认 | 显示申请状态、查看记录；符合规则时提供撤回申请 | 提交成功后只出现一个很快消失的提示，用户找不到申请 |
| 已到店 | 显示实际状态，提供允许的更正办法及记录 | 为了对称仍显示“撤回”，执行后却改变已经发生的事实 |
| 提交请求超时 | 告诉用户结果还未确认，查询是否已有申请，再决定是否重试 | 把超时等同于没有提交，导致用户重复申请 |

记录放在业务对象附近，内容与用户的权限有关。不要为所有小动作新建单独的历史页面，也不要只留下开发日志却让用户无法找到自己的申请。

## 4. 视觉规则服务于内容

| 页面用途 | 可采用的安排 | 不直接照搬的做法 |
| --- | --- | --- |
| 连续处理工单或比较数据 | 稳定的表格与列表，清楚的主要操作，中性阅读背景 | 每行一张巨大卡片、全部状态使用主题色、用横幅挤走业务内容 |
| 品牌或产品展示 | 与主题相关的淡色背景、局部纹理、更有表现力的排版 | 把展示页的大标题与动效复制到每个后台页面 |
| 阅读文章或长说明 | 合适行宽、正文行高和段落间距，清楚的标题层级 | 把大段正文排得像密集数据表，或每句都加粗 |
| 公文预览与导出 | 依据已确认模板设置字体、字号、行距和页面尺寸 | 只凭印象声称符合公文标准；把文档字体扩展到所有按钮和表单 |

采用组件库时先改主题配置，并检查常用按钮、表单、表格和浮层是否一致。主色相同不代表整套界面一致，字体、禁用状态、间距和键盘选中状态也会影响感受。自写组件只抽取实际复用部分，避免为一次小改更换整套技术方案。

## 5. 可操作性的具体检查

下列数字来自 WCAG 2.2 对应条款；它们帮助发现具体问题，不能单凭几项通过宣布整个产品符合标准。

| 项目 | 检查内容 |
| --- | --- |
| 文字对比度 | 一般文字与背景至少 4.5:1；符合标准定义的大字至少 3:1。停用控件、纯装饰和标志等例外按 1.4.3 原文判断 |
| 控件和状态 | 需要看清的控件边界与状态标记检查对比度，按 1.4.11 的适用范围和例外处理；不能只用颜色表达错误 |
| 点击范围 | 2.5.8 的 AA 要求为至少 24×24 CSS 像素或满足间距等例外；触屏设计可以留得更宽，不把 44 像素误写成全部网页的 AA 要求 |
| 窄屏和放大 | 正文、表单在窄屏和放大后仍可阅读、操作；需要二维布局的表格、图等按 1.4.10 的例外处理 |
| 弹窗键盘操作 | 打开后选中合适的内容或控件，Tab 在当前弹窗内移动，能用关闭按钮和 Escape 退出，关闭后回到合理位置；有未保存内容时走已明确的放弃或保留步骤 |

减少动效是本 Skill 的设计要求。WCAG 2.3.3 属于 AAA，不把它混写成全部 AA 合规条件；实现时尊重 `prefers-reduced-motion`，避免用动画本身传递唯一的信息。

## 6. 参考资料及适用范围

查阅日期：2026-10-03。优先参考维护中的一手说明，更新日期与正式标准的状态分别记录。

- [GOV.UK：完成多个任务](https://design-system.service.gov.uk/patterns/complete-multiple-tasks/) 与[确认结果页](https://design-system.service.gov.uk/patterns/confirmation-pages/)：任务分组、进度和完成后的去向。按业务使用，不要求每个短操作另开结果页。
- [Ant Design：抽屉](https://ant.design/components/drawer-cn/)：当前任务中的补充内容和临时操作。组件支持多层抽屉，不等于所有产品都适合多层操作。
- [Ant Design：定制主题](https://ant.design/docs/react/customize-theme-cn/) 与[字体](https://ant.design/docs/spec/font-cn/)：统一主题变量、组件配置、字体用途和中文屏幕阅读。查项目实际版本，不直接套网页上的最新 API 或固定字号。
- [Carbon：Typography](https://www.carbondesignsystem.com/building-blocks/foundations/typography/overview)：页面标注更新于 2026-09-29，区分工作界面和展示内容的字体安排。采用按用途设样式的方法，不要求使用 IBM 的字体和配色。
- [W3C：WCAG 2.2 快速参考](https://www.w3.org/WAI/WCAG22/quickref/) 与[弹窗操作模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)：对比度、键盘、点击范围和窗口操作。检查适用条件与例外，示例代码不能代替实际检查。
- [W3C：中文排版需求](https://www.w3.org/TR/2026/DNOTE-clreq-20260901/)：2026-09-01 的工作组说明草稿，用于查中文字体、标点和换行问题；仍在完善，不作为已经确定的公文标准。
- [NN/g：Modal & Nonmodal Dialogs](https://www.nngroup.com/articles/modal-nonmodal-dialog/)：2017 年的基础研究说明，用于理解中断操作的代价；不把发布时间写成近期，也不据此统一规定所有业务的页面形式。
